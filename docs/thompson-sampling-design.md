# ML Visual Lab：広告配信 × Thompson Sampling 実装設計書

## 1. Codexへの実装指示

既存の `SioComb/ml-visual-lab` に、広告配信を題材としたThompson Sampling（トンプソンサンプリング）の実験教材を追加してください。本書は実装仕様です。新規サイトの作り直し、フレームワーク移行、外部API接続は行わないでください。

- 1試行＝1回の広告表示、クリック＝報酬1、クリックなし＝報酬0。
- Beta–Bernoulli型Thompson SamplingをJavaScriptで実装する。
- 広告カード、事後分布、意思決定の過程、クリック数・CTR・累積期待後悔を可視化する。

- 学習ロジックと描画を分離し、描画・速度・一時停止で抽選結果が変わらないようにする。
- 実装前に `AGENTS.md` と対象コードの最新状態を確認し、実装後は既存テストと追加テストを実行する。本書に挙げた追加ファイル名は提案であり、最新構成に合わせて調整してよい。
- 不要な依存、汎用フレームワーク、バックエンド、実広告SDK、ログイン、永続化、Sites固有コードは追加しない。
- 実装・テスト結果を報告する。リポジトリへのpush・PR作成・本番公開は、その実行時にユーザーから指示された範囲に従う。

## 3. 学習目標と扱う範囲

利用者が次の3点を体験できること。

1. クリック率が未知でも、表示とクリック結果から有望な広告を選べる。
2. データの少ない広告は推定の幅が広いため、再び試される可能性がある。
3. 事後平均が最大の広告が、毎回選ばれるわけではない。各分布から引いた今回の値の最大で選ぶ。

すべて架空の広告・シミュレーションデータ。ユーザー属性、広告文、画像内容をモデルへ入力しない。広告の内容に応じてCTRを予測するモデルではない。文脈付きバンディット、実広告配信、非定常環境、予算・収益最適化、ニューラルネットワーク、別アルゴリズムとの新規比較機能は今回の対象外。

### 広告カード

- 3種類なら広告A・B・C、4種類ならA〜D、5種類ならA〜E。ラベル・凡例・グラフ・配列の個数を同じ設定から生成する。

- カードの手動クリックで広告を配信しない。Thompson Samplingが自動選択することを一貫させる。

- 設定変更後の古いタイマー／描画結果は破棄。runId等は既存の同等処理があれば再利用。

## 6. 学習ロジック

広告iの表示数をNᵢ、クリック数をSᵢとする。

```text
初期値：Nᵢ = 0、Sᵢ = 0、αᵢ = 1、βᵢ = 1

各試行：
1. 更新前のαᵢ・βᵢを使って、全広告から θᵢ ~ Beta(αᵢ, βᵢ) を1つずつ抽選
2. a = argmax θᵢ を今回表示する広告に決定
3. 環境が r ~ Bernoulli(pₐ) を返す
4. Nₐ += 1、Sₐ += r
5. αₐ += r、βₐ += 1 - r
6. 指標と履歴を更新し、今回の判断データを返す
```

重要な区別：

- 実測CTR：Sᵢ / Nᵢ。未表示時は「—」。
- 推定CTR（事後平均）：αᵢ / (αᵢ + βᵢ)。初期は50%。
- θᵢ：その試行で分布から引いた候補値。「真のCTR」「クリックが起きる確率そのもの」「最適広告である確率」と混同しない。
- 真のCTR pᵢ：環境の設定値。学習器の選択関数へ渡さない。
- ε入力は不要。TSの判断を「今回は探索」「今回は活用」と二値に断定しない。
- 全広告を1回ずつ強制表示しない。Beta(1,1)から初回も通常の抽選を行う。
- θが完全同値の場合のみ行動用乱数でランダムに選択。近い数値を丸めて同値にしない。

### Beta乱数

Seed付き一様乱数からGamma乱数を生成し、X ~ Gamma(α,1)、Y ~ Gamma(β,1)、θ = X / (X+Y) とする。Marsaglia–Tsang等の標準的な受容棄却法を実装し、式と採用した出典をコードコメントに残す。今回α・βは常に1以上なので、未使用のα<1対応を必須にしない。

0の対数回避、有限数チェック、乱数の開区間化を明示する。描画用Beta密度の計算とBeta乱数の生成を混同しない。正規乱数のキャッシュを用いるなら乱数ストリーム内に閉じ込め、リセット時に破棄する。

### 再現性

`dist/rl/random.js` の `random()` を利用し、既存Banditと同じく行動用ストリームと広告ごとのクリックストリームを分離する。各広告のk回目表示に対応するクリック乱数が速度や他広告の表示に左右されない構造とする。グラフ・カード・説明更新では乱数を引かない。

同じSeed・広告数・CTR設定・試行数なら、1回ずつ／+100回／自動実行／一時停止を挟んだ実行の結果と最終状態が一致すること。

## 7. 分布と意思決定の可視化

### 時点の整合性

「今回の抽選に使った分布」と「クリック結果を反映した現在の分布」を区別する。

- 既定表示は「学習後の分布」。全広告の現在のBeta分布を描く。
- 「今回の抽選」表示へ切替可能にし、lastTrialに保存した更新前分布とθのマーカーを同時に描く。
- 抽選前のθを学習後の分布から引いた値として表示しない。
- 1回表示は1試行の学習を完了してから、保存済みデータで4段階を短く演出する。演出は乱数や更新処理を実行しない。
- 高速実行では演出を省略し、直近の試行を表示。4段階を単に常時点灯して「順に再生した」と見せない。

### グラフ仕様

- 横軸はCTR 0〜100%。縦軸は確率密度。「高さ＝そのCTRである確率」ではないと補足。
- Beta(1,1)は端点も含めて一定の水平線。0%・100%を機械的に密度0にしない。
- 密度はlog-Gamma等による対数計算で評価し、階乗の直接計算を避ける。
- 高試行数でピークが鋭くなるため、平均・モード・標準偏差付近を含む適応的な描画点を使う。固定の粗い等間隔点だけでピークを落とさない。
- 縦軸は実際の最大密度に合わせる。Mockのような密度25での切り捨てはしない。
- 初期状態は分布が重なる旨を表示。凡例で広告の表示を切り替えられ、非表示にしても学習対象からは除外しない。
- 各広告のα・β・推定CTRはテキストでも確認可能にする。
- クリック数と後悔は別グラフで軸を明示。後悔を10倍する等、説明の必要な便宜的倍率を使わない。
- 時系列の横軸は実際の試行回数。%ラベルを流用しない。長い履歴は描画だけを間引き、初期・最終点を含める。

## 8. 評価指標

| 指標 | 定義とゼロ試行時 |
| --- | --- |
| 表示回数T | 全広告のNᵢの合計。初期0 |
| クリック数C | 全広告のSᵢの合計。初期0 |
| 累積CTR | C/T。初期「—」 |
| 累積期待後悔 | Σₜ (maxᵢ pᵢ − pₐₜ)。初期0。クリック数ではなく期待値の差 |
| 最適広告選択率 | 真のCTRが最大の広告を選んだ回数/T。初期「—」。同率最大はすべて最適として数える |

真のCTRを非表示にしている間は、真値依存の「累積期待後悔」「最適広告選択率」の値も伏せ、「真のCTRを表示すると確認できます」とする。内部計算は続ける。全広告同じCTRなら期待後悔は常に0、1試行後から最適広告選択率100%。

最適広告を毎回表示した場合の期待クリック数T×max pと実クリック数の差を後悔と呼ばない。その差は偶然に負になることがある。TSが必ず最良、または特定Seedで必ず収束するとは説明しない。

## 10. 画面に載せる解説文

### 導入

「クリック率が分からない広告から、どれを表示するかを選びます。Thompson Samplingは、各広告のクリック率の候補を確率分布から1つずつ引き、今回の値が最大の広告を表示します。」

### 分布の読み方

「横軸はクリック率の候補、曲線はその候補の確からしさを表す確率密度です。表示回数が少ないうちは分布が広く、結果が集まると推定が絞られます。曲線の高さ自体はクリック確率ではありません。」

### 初期推定

「最初はBeta(1,1)という一様な事前分布です。推定CTRの50%は実績ではなく、この事前分布の平均です。」

### 探索と活用

「推定CTRが少し低い広告でも、分布から大きな値を引けば選ばれます。未知の広告を試す機会と、有望な広告を使う機会を、サンプリングで両立します。εのような探索率は設定しません。」

### 制約

「広告文や画像の内容は学習していません。各広告のクリック結果だけを使い、CTRが実験中に変わらないと仮定しています。このシミュレーションの結果は、実広告の成果を保証しません。」

## 11. 受入条件・検証

### 決定論的なロジック検証

- 広告数3・4・5で全配列長、カード数、凡例数が一致する。2・6・小数・NaNは拒否。
- 初期分布は全広告Beta(1,1)、countsとclicksは0。
- クリック成功時は選択広告のαだけが1増加、失敗時はβだけが1増加。他広告の分布は不変。
- 毎試行、保存済みsamplesの最大値の広告が選ばれる。真のCTRを書き換えても同じ事前状態と行動乱数からの最初の選択は変わらない。
- α＝1＋clicks、β＝1＋counts−clicks、Σcounts＝T、Σclicks＝C、0≦C≦Tを満たす。
- CTR 0%なら必ずクリックなし、100%なら必ずクリック。全CTR同値なら期待後悔0。
- 同じSeed・設定・試行数で実行方法に関係なく状態・履歴が一致。
- 真値表示切替、描画、リサイズを挟んでも抽選列が不変。
- 3→5→4と変更したら停止・リセットし、削除広告の履歴や選択強調が残らない。
- Gamma/Betaの値は有限、θは0〜1。最大試行数でもNaNや無限ループが発生しない。
- Beta(1,1)・Beta(2,1)・Beta(1,2)の密度を既知の値で確認。鋭い分布もピークを描ける。
- 固定Seedの多数サンプルでBeta乱数の標本平均・分散が理論値の妥当な許容範囲に入ることを確認。揺らぐ「必ず最適広告に収束」をテスト条件にしない。

### UI・回帰検証

- 上限の直前で+100回を実行しても超過しない。一時停止・再開で二重タイマーにならない。
- 自動実行後の「今回の判断」は直近試行と一致し、前回の手動実行結果で止まらない。
- 学習後／今回の抽選の切替で、分布の時点・θ・選択広告が一致。
- CTR編集は確定するまで学習へ反映されない。未確定値・不正値がある状態で実行させない。
- 教材移動・タブ非表示で停止。戻っても結果を壊さず、自動再開しない。
- 390px幅・PC幅・200%文字拡大で操作可能。選択状態と結果を色以外で判別可能。
- キーボード操作、フォームlabel、控えめなaria-live通知、reduced-motion対応。高速実行の全試行を読み上げない。
- 既存スロットのGreedy・ε-Greedy・UCB、迷路、Snake、その他カテゴリの操作とテストを維持。
- `npm run check` と `npm test` を実行。既存方式に合わせたブラウザテストが実行できない場合は未実施として報告。

## 12. 実装順序と完了報告

1. 最新コードの教材切替・停止処理・乱数・スタイルを読む。
2. DOM非依存のTS更新と乱数処理を実装し、不変条件・再現性をテスト。
3. 広告教材を追加し、3〜5種類の設定・カード・1回表示を接続。
4. 事後分布・今回の抽選・指標・グラフを実データに接続。
5. 自動実行・+100回・停止・設定変更・レスポンシブ表示を整える。
6. 回帰テストと画面検証、README更新を行う。

完了時は、変更ファイル、実装した機能、テスト結果、未検証事項・制約を短く報告する。Mockの見た目だけでなく、クリック抽選・Beta更新・Seed再現性まで実際に動くことを完了条件とする。
